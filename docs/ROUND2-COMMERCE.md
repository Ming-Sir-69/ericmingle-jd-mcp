# 京东购物车与商家会话

## 购物车

`add_to_cart(url, sku_text?, qty=1, operation_id?)` 的 qty 是本次新增数量（1至3）。先读取指定SKU的已选规格及购物车目标行，再点击唯一加购控件，最后核对目标行数量增量。目标行初始数量不可见时，必须另外确认新成功提示或详情购物车计数增加，并读到同编号目标行。

operation_id 是一次新增动作的稳定ID。相同ID及参数成功后再次调用返回already、零点击；不同参数复用同ID会拒绝。省略ID时由商品编号、规格参数及数量推导固定ID，明确再次新增必须传新ID。点击前记录待确认状态；异常或结果未知会保持待确认，重启不会重试。不要把同一操作换新ID来绕过待确认状态。

规格必须与当前详情页已选文字完全一致；多规格且未给文本返回needs_sku。单SKU可省略并沿用已选文字；不自动切换规格。数量在唯一输入框内设置，设置后再核身份与数值。数字商品URL编号也是本样例的SKU编号；购物车没有可见规格标签时返回sku_id，sku_text标missing。

`cart_list()` 返回当前渲染商品行，单价/规格文本未取得可靠字段时标missing。complete仅表示可见行与页面购物车总数核对成功；不滚动遍历或声称抓到未渲染数据。

`remove_from_cart(item_id, sku_text?)` 接受数字SKU编号，指定规格时先核详情页已选规格，再删除唯一目标行；数量变化、多行或控件不唯一会拒绝。确认框仅在唯一框内唯一“删除/确定”时确认。删除后读回同编号行消失；目标不存在且全车不完整时不冒称already。

## 商家会话

`merchant_messages(url)` 使用商品编号打开官方jdcs会话，不发送。`contact_merchant(url,text)` 要求明确商品URL及1至500字正文。只有官方会话PID、唯一活动会话收件名和唯一商品卡一致，且唯一输入框没有用户草稿，才输入并单次发送。发送后必须读到新出现的完全一致正文气泡才返回成功；这只说明会话内可见，不表示商家已读。身份变化、风控或未知回执立即停止，不重发。

相同商品和正文的发送记录持久去重，不群发。不向商家发送开发测试消息。本轮实际发送没有验收，离线测试验证了对象错误、歧义、草稿和未知回执路径。

所有操作沿用固定日常Brave任务session、已有30秒业务间隔、持久风控锁与HTTP保护；不会结算、下单或支付。DOM选择器来自本轮真实只读取证；真实站点变化时会拒绝未知控件。
